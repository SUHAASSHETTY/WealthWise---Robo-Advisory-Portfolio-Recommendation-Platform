## Description

`backend/app/domain/risk_band_rules.py` implements the pure functions `score_answers`, `band_for_score`, `apply_caps`, `assess` and `effective_band`, with the policy passed in as a parameter (no module-level points or thresholds). Validation failures raise a domain `AssessmentValidationError` carrying the spec code. Effective band is derived from the newest event; overrides are accepted as an (empty in Sprint 1) input.

## Acceptance criteria

1. **Moderate example (AC-01.2).** `assess(RISK_POLICY_V1, ANS_16)` returns `total_score = 16`, `computed_band = MODERATE`, `assigned_band = MODERATE`, `applied_caps = []`.
2. **Band boundaries (AC-01.3).** `assess(RISK_POLICY_V1, s)` for ANS_0, ANS_11, ANS_12, ANS_20, ANS_21, ANS_28 gives totals 0, 11, 12, 20, 21, 28 and `assigned_band` CONSERVATIVE, CONSERVATIVE, MODERATE, MODERATE, AGGRESSIVE, AGGRESSIVE. ANS_0 and ANS_11 use `EMERGENCY_FUND = NONE` and their band is unchanged by the cap.
3. **Cap (AC-01.4).** `assess(RISK_POLICY_V1, ANS_CAP24)` returns `total_score = 24`, `computed_band = AGGRESSIVE`, `assigned_band = MODERATE`, `applied_caps = ["NO_EMERGENCY_FUND"]`.
4. **Determinism (AC-01.5).** Scoring ANS_16 100 times yields 100 equal `AssessmentResult` objects; answer order in the input does not change the result.
5. **Validation (AC-01.6).** Omitting OBJECTIVE raises code `ANSWER_MISSING`; option `GT_10Y` for `AGE` raises `OPTION_INVALID`; answering AGE twice raises `ANSWER_DUPLICATE`; question `SALARY` raises `QUESTION_UNKNOWN`.
6. **Effective band and policy-as-parameter (AC-01.7, AC-10.6).** `effective_band([], [])` is `None`; with two assessments it returns the newest by (`created_at`, `id`), including tie-break on `id` for equal timestamps. `assess(RISK_POLICY_V2_AC_10_1, ANS_20)` returns `assigned_band = AGGRESSIVE` while v1 returns MODERATE. Branch coverage of the module is 100%.

## Assumption

`applied_caps` lists a cap only when it lowered the band (so ANS_0 / ANS_11 report `[]`). risk_profile §2.3 is silent on caps whose condition matches without effect; flagged for spec confirmation.
