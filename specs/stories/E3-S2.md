## Description

CUSTOMER-only routes `POST /api/v1/recommendations`, `GET /api/v1/recommendations/latest` and `GET /api/v1/recommendations`, backed by `recommendation_service` and `recommendation_repository`. The service reads the effective band from `risk_profile_service`, the active template version, the caller's goals and the injected clock, calls the pure domain, and inserts the recommendation (pinning `template_version_id`), its allocation rows and an audit row in one transaction.

## Acceptance criteria

1. **Template per band, no goal (AC-02.1).** alice submits ANS_16 then `POST /api/v1/recommendations {}` → `201` with `source = "SYSTEM"`, `risk_band = "MODERATE"`, `template_version_no = 1`, `goal_id = null`, `horizon_months = null`, `horizon_rule = "NO_GOAL"`, `allocation = [{EQUITY,"50.00"},{DEBT,"35.00"},{GOLD,"10.00"},{CASH,"5.00"}]` (order EQUITY, DEBT, GOLD, CASH; values JSON strings), `total_pct = "100.00"`. The stored row's `template_version_id` equals v1's id and an `audit_events` row `RECOMMENDATION_CREATED` exists.
2. **Each band (AC-02.2).** bob assessed ANS_0 → recommendation allocation 20.00/60.00/10.00/10.00; bob then assessed ANS_28 → 75.00/15.00/7.50/2.50 (`risk_band` follows the newest assessment).
3. **Failure paths persist nothing (AC-02.5, AC-02.4).** carol (no assessment) → `409 RISK_PROFILE_REQUIRED`. alice with `goal_id` = grace's goal B → `404 GOAL_NOT_FOUND`. With a corrupted PUBLISHED template (MODERATE sum 99.99, inserted by test fixture) as active, the call fails with `AllocationSumError` surfaced as an error response. In every case `recommendations`, `recommendation_allocations` and `audit_events` counts are unchanged.
4. **Horizon adjustment with fixed clock (AC-04.1).** Clock 2026-01-15; frank submits ANS_16 then `POST /api/v1/recommendations {"goal_id": "00000000-0000-4000-8000-0000000f0001"}` → allocation 30.00/55.00/10.00/5.00, `horizon_months = 48`, `horizon_rule = "H_36_59"`, `as_of_date = "2026-01-15"`.
5. **Primary goal (AC-04.3).** Clock 2026-01-15; grace submits ANS_16 then `POST /api/v1/recommendations {}` → `goal_id = "00000000-0000-4000-8000-0000000b0001"`, `horizon_months = 29`, `horizon_rule = "H_12_35"`.
6. **Determinism, append-only, latest/list (AC-04.4, AC-02.3).** Two identical POSTs for frank return identical `allocation`, `horizon_months`, `horizon_rule`, `template_version_no` and distinct `id`s; two recommendation rows exist. `GET /api/v1/recommendations/latest` returns the second; `GET /api/v1/recommendations` returns both newest first; before any recommendation `latest` → `404 RECOMMENDATION_NOT_FOUND`. `tests/architecture/test_allocation_sum_invariant.py` also asserts every stored recommendation sums to `Decimal("100.00")`.

## Consumes

- `risk_profile_service.effective_band` (E2-S2); `recommend`, `horizon_months`, `primary_goal` (E3-S1); seeded goals, clock, customer resolver (E1-S3); active template query (E1-S1/E1-S4 repository).

## Produces

- `recommendation_service.latest_for(customer_id)` (consumed by E3-S3 and later by holdings/drift).
