## Description

Introduce Alembic under `backend/migrations/` with one schema revision that creates every table Sprint 1 needs: `users`, `customers`, `asset_classes`, `risk_policy_versions`, `template_versions`, `goals`, `risk_assessments`, `recommendations`, `recommendation_allocations` and `audit_events`. Add the `RiskPolicyVersion` model (same shape and published-version guard as the existing `TemplateVersion`, which gains `created_by` / `published_by`), plus an `AppendOnlyViolation` guard on the four append-only tables. The test DB fixture builds its schema with `alembic upgrade head`, so every later story runs against the migrated schema.

## Acceptance criteria

1. **Schema + single draft (AC-10.1, AC-10.7).** `alembic upgrade head` on an empty SQLite file creates all 10 tables. `risk_policy_versions` and `template_versions` both have `id, version_no (unique), status, definition (JSON), created_by, created_at, published_by, published_at`, and a partial unique index on `status = 'DRAFT'`: inserting a second DRAFT row into the same table raises `IntegrityError`, while one DRAFT per table succeeds.
2. **Published immutable at persistence (AC-10.3).** For both version models, an ORM update of `definition` or an ORM delete on a row whose persisted status is `PUBLISHED` raises `PublishedVersionMutation`; after rollback the row's `definition` is byte-identical. Editing or deleting a DRAFT row, and the DRAFT → PUBLISHED transition, succeed. `tests/architecture/test_published_templates_immutable.py` covers both models.
3. **Append-only tables (AC-01.7, AC-04.4; NFR-02).** An ORM UPDATE or DELETE on a `risk_assessments`, `recommendations`, `recommendation_allocations` or `audit_events` row raises `AppendOnlyViolation` and the transaction rolls back. `tests/architecture/test_append_only_tables.py` asserts this for all four models, and their repositories expose insert/read methods only.
4. **Decimal storage (AC-02.3; NFR-01).** `recommendation_allocations.target_pct` uses `DecimalText(scale=2)` and `goals.target_amount` uses `DecimalText(scale=2)`. No model has a `Float` or `Numeric` column, and `tests/architecture/test_no_float_money.py` passes over the new models.
5. **No mutable band, locked migrations (AC-01.7; NFR-05, NFR-08).** No table has a `risk_band` / `current_band` column other than the append-only `risk_assessments` and `recommendations` (asserted by `tests/architecture/test_band_reassignment_requires_override.py`). `tests/architecture/test_migrations_locked.py` compares sha256 hashes of revision files against `backend/migrations/LOCKED_HASHES.txt` (format `<sha256>  <filename>`); Sprint 1 revisions are added to the lock when the phase is approved.
