## Description

A second Alembic revision (data migration, literal values only, never importing app code) inserts the synthetic seed: asset classes, v1 risk policy, v1 templates, 7 users, 5 customers and a few read-only goals with fixed IDs. The stub-token table gains `stub-token-frank` and `stub-token-grace`, and a customer-resolution helper maps a CUSTOMER principal to its `customer_id`. The app gets an injectable `Clock` on `app.state.clock` (overridable by `WEALTHWISE_FIXED_CLOCK` for tests and the evaluator) so horizon calculations are deterministic.

## Acceptance criteria

1. **Policy seed (AC-01.1, AC-02.1, AC-10.1).** After `alembic upgrade head`: `asset_classes` holds EQUITY, DEBT, GOLD, CASH (display_order 1–4, all active); `risk_policy_versions` holds exactly one row, `version_no = 1`, `PUBLISHED`, whose definition is the 7-question / 3-band / 1-cap policy from risk_profile §2; `template_versions` holds exactly one row, `version_no = 1`, `PUBLISHED`, equal to the admin_versioning §2.3 JSON. Both definitions pass the E1-S2 validators, and `tests/architecture/test_allocation_sum_invariant.py` loads every PUBLISHED template from the migrated DB and asserts each band sums to `Decimal("100.00")`.
2. **Users and customers (AC-02.5, AC-10.6, AC-10.8).** `users` holds alice.customer, bob.customer, carol.customer, frank.customer, grace.customer (CUSTOMER), dan.advisor (ADVISOR), erin.admin (ADMIN). Each CUSTOMER has one `customers` row; carol has `kyc_verified = false`, the others `true`. No risk assessments, recommendations or audit events are seeded.
3. **Seeded goals (AC-04.1, AC-04.3, AC-02.1).** `goals` holds exactly: frank `00000000-0000-4000-8000-0000000f0001` (priority 1, target_date 2030-01-15); grace A `00000000-0000-4000-8000-0000000a0001` (priority 2, 2040-01-01); grace B `00000000-0000-4000-8000-0000000b0001` (priority 1, 2028-06-30). alice, bob and carol have no goals. `target_amount` values are decimal strings.
4. **Principal → customer (AC-04.3, AC-10.8).** `stub-token-frank` and `stub-token-grace` authenticate as CUSTOMER. `CustomerResolver.customer_id_for(principal)` returns the seeded customer id for each of the 5 customer usernames and raises for ADVISOR/ADMIN principals. Customer IDs are never taken from a path parameter.
5. **Injectable clock (AC-04.1, AC-04.4).** `create_app(settings, clock=None)` stores `SystemClock()` on `app.state.clock` by default; with `WEALTHWISE_FIXED_CLOCK=2026-01-15T09:00:00Z` (or an explicit `FixedClock`) every request sees `today() == 2026-01-15`. A `get_clock` dependency in `api/deps.py` exposes it; no module under `domain/` or `services/` calls `date.today()` / `datetime.now()` (grep-based architecture test).
