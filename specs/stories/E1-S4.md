## Description

ADMIN-only routes under `/api/v1/admin/risk-policies` and `/api/v1/admin/template-versions`: list, get, create draft (copied from the active version), edit draft, delete draft and publish. A shared `policy_version_service` enforces the lifecycle (single draft, published immutable, publish validation through `template_version_validator`) and writes audit events in the same transaction. Asset-class admin routes and NAV refresh are out of scope.

## Acceptance criteria

1. **Versioned risk policy (AC-10.1).** As erin: `POST /api/v1/admin/risk-policies/drafts` → `201` with `version_no = 2`, `status = "DRAFT"` and a definition equal to v1; `PUT /api/v1/admin/risk-policies/{v2_id}` with bands MODERATE 12–19 and AGGRESSIVE 20–28 → `200`; `POST …/{v2_id}/publish` → `200 {"version_no": 2, "status": "PUBLISHED"}`. `GET /api/v1/admin/risk-policies` then lists v1 and v2 both `PUBLISHED`, v1's definition is byte-identical to before, and the service's active policy is v2. Audit rows `POLICY_DRAFT_CREATED`, `POLICY_DRAFT_UPDATED`, `POLICY_PUBLISHED` exist with `details` holding only ids/version numbers.
2. **Published immutable via API (AC-10.2).** `PUT /api/v1/admin/template-versions/{v1_id}` → `409 POLICY_VERSION_IMMUTABLE` and a subsequent `GET …/{v1_id}` returns a byte-identical definition; `DELETE …/{v1_id}` → `409 POLICY_VERSION_IMMUTABLE`; `POST …/{v1_id}/publish` → `409 ALREADY_PUBLISHED`. Same behaviour for `/admin/risk-policies/{v1_id}`.
3. **Publish validation (AC-10.4).** A template draft whose AGGRESSIVE GOLD is `"7.51"` (sum 100.01) → publish returns `422 TEMPLATE_INVALID` with `error.details.violations` containing a message naming `AGGRESSIVE` and `sum=100.01`; the draft stays `DRAFT` and the active template stays v1. An invalid risk-policy draft (5 questions) → `422 POLICY_INVALID`. A PUT whose template percentage is a JSON number → `422 DECIMAL_MUST_BE_STRING`.
4. **Single draft and draft deletion (AC-10.7).** With a risk-policy draft present, `POST /api/v1/admin/risk-policies/drafts` → `409 DRAFT_EXISTS` (same for template-versions). `DELETE` on the draft → `204`, after which a new draft can be created (`201`).
5. **Role boundary (AC-10.8).** Every `/api/v1/admin/*` route returns `403 FORBIDDEN_ROLE` for `stub-token-alice` (CUSTOMER) and `stub-token-dan` (ADVISOR), and `401 UNAUTHENTICATED` without a token. `tests/architecture/test_routes_declare_roles.py` asserts every non-public route declares `require_role`.
